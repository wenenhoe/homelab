# Coding-Agent Network Zone as Code

Replaces the hand-maintained rules from [`coding-agent-network.md`](coding-agent-network.md) with Tofu-managed ones. A separate project because it waits behind the OPNsense migration chain, while the zone itself must not.

## Scope

The interface, rules, and egress-proxy configuration for the zone, expressed in Tofu, with drift detected against the topic doc. Not in scope: changing the policy itself.

## Decision

No decision of its own. It carries out the last bullet of [ADR 0053 (Coding-agent network reach)](../decisions/0053-network-reach-of-the-coding-agent-host/revision-000.md)'s Decision. It links no `decision:` because that revision becomes `accepted` when the network project completes, while this one is still waiting.

## Execution plan

Update at the start and end of each PR that works a stage.

| # | Stage | Status | Exit condition |
| :-: | :--- | :--- | :--- |
| 1 | Express the interface and rules in Tofu | Not started | A plan against OPNsense shows no diff from the hand-built state |
| 2 | Express the proxy configuration | Not started | The proxy's allowlist is generated from one source in the repo |
| 3 | Retire the hand-maintained state | Not started | The topic doc describes Tofu as the owner, and canary probes still pass |

Stage status is `Not started`, `In progress`, or `Done`.

## Acceptance criteria

- [ ] `tofu plan` shows no diff between the code and OPNsense.
- [ ] The canary probes from [`coding-agent-network.md`](coding-agent-network.md) still pass after the cut-over.
- [ ] The topic doc names Tofu as the owner of the rules.

## Risks

- The OPNsense day-2 chain has no fixed date, and the hand-built rules stay authoritative until it lands.

## Open items

- Whether the proxy's allowlist is generated by Tofu or by Ansible.
