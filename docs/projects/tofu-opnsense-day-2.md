# OPNsense Day-2 Config via API

Brings OPNsense's day-2 configuration (VLAN interfaces, firewall rules and Kea) under Tofu through its config API, so the hand-built zones stop drifting and the rules that are the network boundary are reviewed as code. It needs Tofu's skeleton, state backend and credentials from [`tofu-vm-provisioning.md`](tofu-vm-provisioning.md)'s Stage 1. It does not wait for [`tofu-migration.md`](tofu-migration.md) or the VMID→IP mapping, which only the DNS records use ([`tofu-vm-dns.md`](tofu-vm-dns.md)).

## Scope

VLAN interfaces, firewall rules and Kea for the existing zones, then the coding-agent zone's interface, rules and egress-proxy configuration ([`coding-agent-network.md`](coding-agent-network.md)), expressed in Tofu, with drift detected against the topic doc. Not in scope: Phase 1 (VM shell and ISO), in [`tofu-vm-provisioning.md`](tofu-vm-provisioning.md), DNS for Tofu-provisioned VMs ([`tofu-vm-dns.md`](tofu-vm-dns.md)), and changing any policy.

## Decision

No decision of its own. Stages 3 to 5 carry out the last bullet of [ADR 0053 (Coding-agent network reach)](../decisions/0053-network-reach-of-the-coding-agent-host/revision-000.md)'s Decision. It links no `decision:` because that revision becomes `accepted` when the network project completes, while this one is still waiting. If Stage 1 leaves more than one workable provider, the choice is an ADR before Stage 2.

## Acceptance criteria

- [ ] `tofu plan` shows no diff between the code and OPNsense for VLAN interfaces, firewall rules and Kea.
- [ ] The coding-agent zone's interface, rules and proxy configuration are expressed in Tofu, and the canary probes from [`coding-agent-network.md`](coding-agent-network.md) still pass after the cut-over.
- [ ] The proxy's allowlist is generated from one source in the repo.
- [ ] The topic doc names Tofu as the owner of the rules.
- [ ] The provider's API key is held where ADR 0048 decides.

## Risks

- The hand-built rules stay authoritative until Stage 5, and drift until then.
- An import of live rules may show differences the provider cannot express; Stage 1 lists them.
- A plan applied to the live gateway changes live rules, so Stage 2 only plans until one shows no diff.
